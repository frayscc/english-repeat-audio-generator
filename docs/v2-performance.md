# V2 性能记录

日期：2026-09-11  
测试机：Mac mini / Apple M4 / 16 GB / macOS 26.6.2  
V2 后端：Kokoro 82M q8 / 原生 ONNX Runtime CPU / 最多 4 线程

## 体积与内存

| 指标 | V1 | V2 macOS |
| --- | ---: | ---: |
| 用户入口 | 约 151 MiB 单 HTML | 128 MiB `.app` |
| HTML | 约 151 MiB，含所有 Base64 | 4.6 KiB 外壳 |
| 前端 JS/CSS | 包含在 HTML | 约 20 KiB + 9.5 KiB |
| 正式模型与 Voice 资源 | Base64 内嵌 | 约 91 MiB 原始文件 |
| 压力运行 RSS | 约 1.96 GiB（Chrome） | 完成后约 401 MiB；观测峰值约 458 MiB |

V2 应用仍包含约 96 MB 的 q8 模型；“轻量化”主要来自取消 Base64、移除发行版 WASM/q8f16、避免浏览器 ONNX Runtime 重复打包，以及降低运行内存，而不是更换已经验证过音质的模型。

发音修复后，WebView 端不再打包临时 JavaScript G2P，前端 JavaScript 从约 5.1 MiB 降到约 20 KiB；eSpeak NG 英语数据和代码由原生程序随包提供，不联网下载。

## 初始化与推理

| 指标 | V1 | V2 Release |
| --- | ---: | ---: |
| 模型 Ready | 首次点击后长时间等待 | 应用启动后台初始化，实测约 0.26 s |
| `hello` 首次开发烟测 | 未单独记录 | 初始化 + 合成约 0.85–1.00 s，33,000 samples |
| `environment` | 未单独记录 | 0.82 s |
| `protect the environment` | 未单独记录 | 0.96 s |
| 50 个不同常用单词 | 未单独记录 | 58.45 s |
| 100 个不同常用单词 | V1 100 项约 423.9 s | 209.67 s |

50/100 项基准使用同一组 100 个唯一常用单词，在第 50 条记录中点，避免 LRU 命中。它是连续推理压力测试，不代表重复试听；相同 `text + voice + speed` 的第二次试听直接命中缓存，应接近即时返回。V1 的原始 100 项词表未保存，因此“约快一倍”只能视为同类压力对照，不是严格同输入统计。

## 解读

- 窗口显示与模型初始化解耦，解决“点第一次试听才开始加载”。
- 单条生成仍约 1 秒，不能显示伪造百分比，因此 UI 使用真实阶段与已用时。
- 原生后台线程避免 UI 假死；它并没有让 Kokoro 82M 的每条计算成本消失。
- 100 条总时长主要取决于每条发音长度。进度是精确完成数，ETA 只在 3 条后出现。
- 两层 LRU 让重复教学词条不再重复推理，同时以 128 项/256 MiB 限制长期内存。
